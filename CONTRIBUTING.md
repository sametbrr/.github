# Contributing

Thanks for taking the time to contribute. This guide applies to every public repository under
[github.com/sametbrr](https://github.com/sametbrr) unless a repository ships its own
`CONTRIBUTING.md`.

> 🇹🇷 Türkçe için [CONTRIBUTING.tr.md](CONTRIBUTING.tr.md)

## Ways to contribute

| You want to | Go to |
|---|---|
| Ask a question, share an idea or show what you built | the repository's **Discussions** tab |
| Report a bug | a new **Issue** using the bug report form |
| Request a feature | a new **Issue** using the feature request form, or an Ideas discussion |
| Report a security vulnerability | **Security → Report a vulnerability** (never a public issue), see [SECURITY.md](SECURITY.md) |
| Fix something | a pull request (see below) |

Issues and discussions in English or Turkish are both welcome.

## Pull requests

1. For anything bigger than a typo, open an issue or discussion first so we can agree on the approach.
2. Fork the repository and create a branch from the default branch (`main` or `master`).
3. Keep the change focused: one fix or feature per pull request.
4. Follow the existing code style and run the checks the repository documents (tests, linters,
   `claude plugin validate .` for agent plugins).
5. Update the documentation that your change affects. Repositories with a `README.tr.md` keep it
   in sync with `README.md`.
6. Use a clear commit message, preferably [Conventional Commits](https://www.conventionalcommits.org/)
   (`fix: …`, `feat: …`, `docs: …`).
7. Fill in the pull request template and link the related issue.

Releases, version bumps and tags are handled by the maintainer.

## Good first issues

Issues labelled [`good first issue`](https://github.com/search?q=user%3Asametbrr+label%3A%22good+first+issue%22+state%3Aopen&type=issues)
are small and well-scoped, a good starting point.
